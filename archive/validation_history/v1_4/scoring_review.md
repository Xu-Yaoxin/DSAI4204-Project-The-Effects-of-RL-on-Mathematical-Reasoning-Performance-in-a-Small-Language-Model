# v1.4 本地判分修复与重评分复核

判分器（verifier）读取已保存的回答，用精确有理数比较最终数值和原数据集标准答案。判分、回归测试和配对 bootstrap 都只需 Python 标准库；没有加载模型、生成回答或联网。

## 修改与验证

- 修复 `Answer: #### 5` 的重复候选误判、`answer is: 5` 的分隔符解析。
- 支持完整的 `<answer>5</answer>` 数值包装、CRLF、有后续数值的空答案标题、完整粗体答案标签；相互矛盾的明确答案仍被拒绝。
- 保留精确整数/小数/分数等价、无 gold 参与的答案提取、非法表达式拒绝、格式与截断独立记录。
- 全部 18 组 CPU 测试通过，耗时约 38 秒。包含原有 37 个判分案例、新增 118 个回归场景、31 个统计场景、27 个离线复核场景及 30 个训练奖励接口场景。
- 23 个生产 Python 脚本均通过无自定义函数/类的语法检查。离线测试主动阻断网络和模型包导入；一键入口与分析使用 `python -S`。
- 已实际运行一键入口，重评 8,800 条回答；再次运行完成输入与结果哈希校验并复用。原始归档保持不变。

## 保守规则的具体边界

以下四条回答的最终数值与 gold 一致，但新规则把未完成或非数值的明确答案段视为提取失败。它们不是四条新发现的数学错误。

| Base 样本 | 被拒绝的原因 |
|---|---|
| gsm8k-test-000129 / 6 | 粗体 Final Answer 标题后是自然语言句子，然后才出现 `#### 10000`。 |
| gsm8k-test-001126 / 7 | 完整 `#### 50` 后又出现空 `Answer:` 标题。 |
| gsm8k-test-000432 / 13 | Final Answer 标题后是自然语言句子，之后才有数值 30 和 `#### 30`。 |
| gsm8k-test-001221 / 10 | 粗体 Final answer 标题后是带单位的自然语言句子，然后才出现 `#### 10`。 |

当前协议要求明确答案候选为单一可解析数值，不猜测句子中的哪个数字是答案。这一规则对 Base/RL 一致适用；相关边界在回归测试中保留。要改变该规则，需要新评分协议和新的结果目录，不能只修正这四条或覆盖本次结果。

数值正确仍不等于整段推理有效；尚未解析的自然语言、单位或不完整回答可能产生保守漏判。修复是在看到本次输出后进行的，因此这份结果是事后评分敏感性分析，不是新规则下的独立确认实验。旧 GRPO 已经收到的奖励不会被重评分追溯修正，剩余 14.25 pp 也不能直接称为纯数学推理提升。
