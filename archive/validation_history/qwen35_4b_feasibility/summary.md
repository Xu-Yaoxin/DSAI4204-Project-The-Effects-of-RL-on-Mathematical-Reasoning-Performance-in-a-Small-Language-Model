# Qwen3.5-4B-Base 可行性与实验选择记录

日期：2026-10-30。结论：4B 已通过官方元数据、模型结构和 LoRA 挂载预检查；结合 2B pilot 的实测显存，单张 24GB RTX 4090 上继续采用 BF16 LoRA-GRPO 有合理的容量依据。4B 尚未通过真实 GPU 训练验收，当前可执行流程仍只接受 2B。

研究设计建议：保留正在进行的 2B 主实验，将 4B 作为下一组规模对照候选。这个建议依据当前研究问题、已有训练信号和计算预算，并不预判哪种模型会支持假设。

## 本次实际验证

从官方仓库读取固定版本的配置、文件索引及全部 safetensors 文件头，未下载权重数据。4B revision 为 `1001bb4d826a52d1f399e183466143f4da7b741b`。配置和索引通过官方 Git blob 身份校验；Range 响应的范围、长度已校验。文件头记录与模型索引一致，但完整权重文件的 SHA-256 尚未验证。

在隔离的 Mac ARM64 环境中使用 PyTorch 2.10.0、Transformers 5.3.0、PEFT 0.18.1、Accelerate 1.10.1，构建完整尺寸的 meta 模型，再按项目当前目标模块规则挂载 rank 16 LoRA。meta 张量没有实际存储，因此该检查验证结构和参数关系，不验证数值计算或 GPU 显存。

| 项目 | 2B | 4B |
|---|---:|---:|
| 文本骨干参数量 | 1,881,825,088 | 4,205,751,296 |
| 全部转为 BF16 后的文本权重 | 3.5052 GiB | 7.8338 GiB |
| LoRA 可训练参数量 | 10,911,744 | 21,233,664 |
| LoRA 目标模块数 | 96 | 128 |
| 官方文本权重张量的键名和形状 | 320 个全部匹配 | 426 个全部匹配 |
| 共享输入输出嵌入 | 保持 | 保持 |

2B 的 LoRA 参数量和用户服务器训练日志完全一致。4B 的文本权重比 2B 大约 2.235 倍；这不是训练峰值或耗时的倍数预测。下载的完整 4B 检查点还包括视觉塔和 MTP 权重，不能把全仓库文件大小等同于本项目文本骨干的显存。

用户提供的 2B pilot 报告：allocated 峰值为 4.0115 GiB，reserved 峰值为 4.1309 GiB，训练耗时约 3.645 小时。SSH 只读尝试未通过认证；这份数据的来源是用户贴回的报告字段，不是本地直接采集。它支持当前 2B 配置显存余量较大的判断。

4B 已知的生成缓存分量，在 8 路生成、768-token prompt 加 512-token completion 上限下约 0.6992 GiB。这个分量不包含权重、激活、临时工作空间或分配器保留；不能与网页曲线简单线性外推成总峰值。具体计算见 [review.md](review.md) 和 [memory_components.json](memory_components.json)。

## 对实验假设的影响

原始 proposal 第 1 页第 1 节要求检验：RLVR 提升单次成功率，且单次增益大于 16 次采样成功率的增益。第 2 页第 3 节还比较数值变体和关系变体上的增益。16 次采样对应有限预算下的覆盖，不能证明绝对推理能力边界。

当前日志显示 2B 可以产生正确回答和有差异的组内奖励，尚无证据表明它陷入完全无学习信号的地板效应。独立开发集的能力和训练收益仍待测量。

4B 可能缓解模型太弱的问题，也可能更接近评测天花板。例如，假设某个模型的 Base pass@16 已有 98%，它在该指标上最多再提高 2 个百分点；若 pass@1 提高 5 个百分点，就自然满足“单次增益更大”。这是说明指标上限的假设例子，不是 4B 实测，也不能单独证明 RLVR 只重新分配了已有能力。

因此，目前建议 2B 为主、4B 为规模对照。若相同独立开发题目的比较显示 2B 严重受地板效应影响，而 4B 有合适的提升空间，再登记更换主模型的理由。选择不能依据最终测试集哪一组更符合预期结论；已完成的 2B 结果应保留。两组比较分别使用 2B Base 对 2B RL、4B Base 对 4B RL，相同数据和更新数之外另报 GPU 小时。

详见 [hypothesis_review.md](hypothesis_review.md)。原论文使用更高的采样预算，本项目是较小规模概念复现，不能把 pass@16 直接解释为穷尽模型全部可解题目。

## 下次采用 4B 前的必要工作

1. 新增独立的 4B 模型配置、固定版本下载清单与输出目录，适配当前显式锁定 2B 的加载检查；保持 2B 实验记录。
2. 在空闲目标 4090 上验证完整权重加载、8 路生成、GRPO 前向/反向和优化器更新、冻结底座及 LoRA 参数审计、检查点保存与恢复。覆盖最长真实题目及长度边界压力测试，并记录训练和评测的 allocated/reserved 峰值、速度及剩余显存。
3. 使用开发集检查两个 Base 模型的 pass@1/pass@16、格式和截断率、逐题难度与耗时，再决定 4B 的正式实验预算。主测试集继续独立。

本次未改动生产训练脚本、配置、依赖锁或远端进程；没有启动 4B 下载、GPU 训练或质量评测。当前预检查可支持“4B 值得进入短程 GPU 验收”，不能支持“4B 已在 4090 上训练通过”或“4B 一定更适合假设”。
